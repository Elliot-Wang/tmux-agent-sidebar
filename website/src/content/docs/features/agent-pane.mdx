The sidebar renders one row per agent pane across all tmux sessions and windows. Each row is packed with live metadata pulled from the agent's hooks and from tmux itself.

## Filter bar

The top row of the sidebar filters the agent list by status. Each entry is an icon + live count; selecting one hides rows whose status doesn't match.

### Status filter

- `≡N` — all panes
- `●N` — running, including live background commands
- `◐N` — waiting
- `○N` — idle
- `✕N` — error

Cycle with `h` / `l` (or `←` / `→`), or click an entry. `Tab` advances through the filter one step at a time.

### Repo filter

Below the status row, a repo selector (`▾`) narrows the list to a single repository. Open it with `r` or by clicking the arrow; `—` means no repo filter is active.

## Row elements

### Status icon

- `●` running, including live background commands
- `◐` waiting
- `○` idle
- `✕` error

An agent actively using tools displays as running. A permission prompt that
requires your action displays as waiting even if a background command is still
alive. Other live background commands stay under running; when they exit and
there is no further activity, the pane becomes idle.

### Permission badge

- `plan` — plan mode
- `edit` — auto-edit
- `auto` — auto-accept
- `dontAsk` — skip every permission prompt for the session
- `defer` — wait for an explicit decision before applying
- `!` — bypass permissions (dangerous)

### Session name

Defaults to the agent name. Can be changed through Claude Code's `/rename`.

### `+` marker

Indicates the pane sits in a git worktree (any worktree, not only sidebar-created ones). Sidebar-spawned worktrees additionally show a `×` button for one-keystroke teardown. See [Worktree](/tmux-agent-sidebar/features/worktree/) for details.

### Branch

Current Git branch for the pane's cwd. Claude updates dynamically through the `CwdChanged` hook.

### Elapsed time

Time since the last user prompt.

### Task progress

Synchronized from the agent's task list. Each task gets a glyph for its state; the trailing count is `completed/total`.

- `✔` — completed
- `◼` — in progress
- `◻` — pending

```text
  ✔✔◼◻ 2/4
```

### Background shell

Shown when an agent explicitly starts a Bash tool in the background, such as a long-running `npm run dev` or watch command. These commands are included in the running count. Detection requires an explicit background flag in the hook payload; command text alone is not guessed.

The row body surfaces the actual command so you can tell at a glance what is running, and keeps it visible while the agent performs other tool calls. Only the most recent background Bash is tracked; if the agent launches a second one, it overwrites the first in the row. The marker clears automatically when the process exits (via a `ps` liveness sweep each refresh tick).

```text
  npm run dev
```

If the hook payload omitted the command string for some reason, the row shows a `(background shell)` placeholder to indicate that a background command was reported.

Once the underlying process exits, the sidebar's next refresh tick (about once a second) scans `ps` for the stored command, clears the row, and returns an otherwise inactive pane to idle. The `(background shell)` placeholder is exempt from the sweep — without a real command we cannot verify liveness, so it persists until SessionEnd.

### Subagent tree

Parent-child branches for spawned sub-agents. Middle entries use `├`, the last uses `└`. Each row shows the subagent kind followed by `#<id>`.

```text
├ Explore #a1b2
├ Plan    #d4e5
└ Bash    #dead
```

### Listening ports

Localhost ports the pane's process is listening on.

### Response arrow (`▷`)

Preview of the latest agent response.

### Prompt text

Latest user prompt.

### Wait reason

Why the agent is waiting — populated from Claude's `Notification`, `PermissionDenied`, and `TeammateIdle` hooks.
